# PDF highlights into a paper note

Highlights made in Obsidian's PDF viewer live only in the annotation dictionary,
so nothing carries them into the note. This is the two-stage path that does.

```text
highlights <key>          you                    highlights --apply
    PDF  ─────────────►  quotes.json  ─────────►  groups.json  ─────────►  note
         verbatim text   order numbers  group     {heading: [order,…]}     `## Notes`
```

Inside a uv project that depends on the package, prefix the commands with `uv
run`.

## The hard constraint

**You never handle a quote's text.** The extractor emits quotes with an `order`
number, you write a grouping of *order numbers*, and the CLI resolves those back
to the extractor's own bytes. This is not a style rule — it is why the grouping
file holds integers.

You may **order**, **partition** and **label**. Nothing else.

Page 4 of `yen2023soilpowered` reads `low envrionmental impact`. That is a typo
in the published paper, and anything that tidies it makes the note misquote its
source. So quotes are never edited, merged, split, or dropped:

| Looks wrong | Is | Do |
|---|---|---|
| lowercase opening, no full stop | correct output | leave it |
| unbalanced parens | correct output | leave it |
| two adjacent fragments of one sentence | correct output | leave both, unmerged |
| starts mid-word (`ittle has been done to…`) | a bad **selection** | say so, leave it — fixing means re-highlighting in Obsidian |

## The steps

```sh
research-assistant highlights <key> > /tmp/quotes.json   # verbatim, no model
```

Each entry is `{"order": 63, "page": 21, "text": "…", "group": "…" | null}`,
where `group` is the heading that quote already sits under in the note.

1. **Read the JSON.** If it is `[]`, the PDF has no highlights — say so and
   stop. Note anything reported on stderr as skipped: a free-draw highlight has
   no geometry and cannot be recovered.
2. **Keep what is already grouped.** A quote with a non-null `group` stays under
   that heading, spelled exactly as it is. Only place the `"group": null` ones,
   into a fitting existing heading or a new one. This keeps the diff
   proportional to what actually changed. Regrouping wholesale is a manual act —
   only do it if asked.
3. **Write the grouping** as `{heading: [order, …]}`, headings in the order they
   should appear, orders in the order they should appear beneath. Every order
   must appear **exactly once**; the CLI rejects a grouping that drops, repeats
   or invents one.
4. **Apply it:** `research-assistant highlights <key> --apply /tmp/groups.json`
5. **Show what changed.** `git diff` does not cover the vault — read the note
   back with `research-assistant show <key>`.

## Headings

`###`, in your own words, and the **only generated bytes in the note**. Name the
idea the quotes share — `SMFC power output`, `Why not solar` — not the section of
the paper they came from. A heading with one quote under it is fine; a heading
per quote is not a grouping.

## What it writes

One quote is one bullet, closed by a bracketed link to its page. A tight list:
nothing between the bullets.

```markdown
### SMFC power output

- produce as much as 200 µW ([[yen2023soilpowered.pdf#page=2|p. 2]])
- open-circuit voltage upwards of 731 mV ([[yen2023soilpowered.pdf#page=2|p. 2]])
```

Long quotes wrap at 88 columns with continuation lines indented two spaces; the
link wraps as one token, so it is never split across lines.

## The region boundary

`## Notes` has no delimiters, so the contract is positional:

| Region | Owner |
|---|---|
| everything **before** the first `### ` | the user's prose — reattached unchanged |
| everything **from** the first `### ` on | machine-owned |

Do not write `### ` headings into the prose half, and do not hand-edit the
machine half — change the grouping and re-apply. Bullets of your own above the
first heading are fine; only a `### ` opens the machine region.

## When it goes wrong

| Symptom | What it means |
|---|---|
| `has no PDF on disk` | The note has no PDF. `pdf <key>` says whether a `pdf_url` was recorded. |
| `no ## Notes heading` | Run `tidy` first. Do not synthesise the section. |
| `grouping drops N highlight(s)` | Every order must be placed. Add the missing ones. |
| stderr says `skipped N free-draw` | Those highlights were drawn, not selected. Report it; nothing is recoverable. |

`highlights --audit` re-derives every quote in the vault from its PDF and
reports any that no longer match, with both strings. It is the check that a
quote was never quietly altered — run it if a note looks edited.
