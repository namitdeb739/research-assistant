# PDF highlights into a paper note

Highlights made in Obsidian's PDF viewer live only in the annotation
dictionary, so nothing carries them into the note. This is the two-stage path
that does: `research-assistant highlights` recovers the text, you group it, and
the CLI writes it.

Inside a uv project that depends on the package, prefix the commands with
`uv run`.

## The hard constraint

**You never handle a quote's text.** The extractor emits quotes with an `order`
number, you write a grouping of *order numbers*, and the CLI resolves those back
to the extractor's own bytes. This is not a style rule — it is why the grouping
file holds integers.

Page 4 of `yen2023soilpowered` reads `low envrionmental impact`. That is a typo
in the published paper. Anything that tidies a quote makes the note misquote its
source, so quotes are never edited, merged, split, or dropped. Lowercase
openings, absent full stops, unbalanced parens and mid-word starts are all
correct output. A quote that starts mid-word (`ittle has been done to…`) is a
bad *selection*: say so, and leave it. Fixing it means re-highlighting in
Obsidian.

You may **order**, **partition** and **label**. Nothing else.

## The steps

```sh
research-assistant highlights <key> > /tmp/quotes.json   # verbatim, no model
```

Each entry is `{"order": 63, "page": 21, "text": "…", "group": "…" | null}`.
`group` is the heading that quote already sits under in the note.

1. **Read the JSON.** If it is `[]`, the PDF has no highlights — say so and
   stop. Note anything reported on stderr as skipped: a free-draw highlight has
   no geometry and cannot be recovered.
2. **Keep what is already grouped.** A quote with a non-null `group` stays under
   that heading, spelled exactly as it is. Only place the ones with
   `"group": null`, into a fitting existing heading or a new one. This keeps the
   diff proportional to what actually changed. Regrouping wholesale is a manual
   act — only do it if asked.
3. **Write the grouping** as `{heading: [order, ...]}`, headings in the order
   they should appear, orders in the order they should appear beneath. Every
   order must appear exactly once; the CLI rejects a grouping that drops,
   repeats or invents one.
4. **Apply it:**

```sh
research-assistant highlights <key> --apply /tmp/groups.json
```

5. **Show what changed.** `git diff` does not cover the vault — read the note
   back with `research-assistant show <key>`.

## What it writes

One quote is one bullet, closed by a bracketed link to its page. A tight list:
nothing between the bullets.

```markdown
### SMFC power output

- produce as much as 200 µW ([[yen2023soilpowered.pdf#page=2|p. 2]])
- open-circuit voltage upwards of 731 mV ([[yen2023soilpowered.pdf#page=2|p. 2]])
```

Long quotes wrap at 88 columns with continuation lines indented two spaces; the
link wraps as one token, so it is never split across lines.

Quotes are never merged, even when two selections are adjacent fragments of one
sentence: what was selected is what appears.

## Headings

`###`, in your own words, and the only generated bytes in the note. Name the
idea the quotes share — `SMFC power output`, `Why not solar` — not the section
of the paper they came from. A heading with one quote under it is fine; a
heading per quote is not a grouping.

## The region boundary

`## Notes` has no delimiters, so the contract is positional: everything before
the first `### ` heading is the user's prose and is reattached unchanged;
everything from that heading on is machine-owned. Do not write `### ` headings
into the prose half, and do not hand-edit the machine half — change the grouping
and re-apply. Bullets of your own above the first heading are fine; only a
`### ` opens the machine region.

## When it goes wrong

| Symptom | What it means |
|---|---|
| `has no PDF on disk` | The note has no PDF. `pdf <key>` says whether a `pdf_url` was recorded. |
| `no ## Notes heading` | Run `tidy` first. Do not synthesise the section. |
| `grouping drops N highlight(s)` | Every order must be placed. Add the missing ones. |
| stderr says `skipped N free-draw` | Those highlights were drawn, not selected. Report it; nothing is recoverable. |

`research-assistant highlights --audit` re-derives every quote in the vault from
its PDF and reports any that no longer match, with both strings. It is the check
that a quote was never quietly altered — run it if a note looks edited.
